## 1. Что это за приложение

Life — приложение для любого человека: день, главная цель, деньги и долги. Регистрация открыта; новый человек начинает с чистого листа (первая настройка из 3 шагов), владелец — со своими данными.
Работает на Android (APK), в браузере (GitHub Pages) и на Windows (EXE); данные общие через Supabase.
Язык интерфейса — русский, валюта по умолчанию — сомони (выбирается в первой настройке), часовой пояс — устройства.

## 2. Архитектура

- **Одно веб-ядро** — `index.html` (~5 400 строк: вся разметка, CSS и JavaScript внутри, без фреймворков и сборщиков).
  Рядом: `sw.js` (офлайн), `manifest.webmanifest`, иконки, `fonts/` (Manrope, Nunito, Inter — woff2), `sounds/jamal-dawn.wav` (делает `tools/make-dawn.py`; с 74.1 — мелодия дважды, 3,5 с, пик 0,95, средняя −11,9 dBFS).
- **Android** (`android/`): Java, WebView + WebViewAssetLoader (`https://appassets.androidplatform.net/assets/`),
  мост `AndroidBridge` (версия 5): уведомления с кнопками «Готово / Через 15 мин» (`ActionReceiver`, `PendingActions`),
  будильники (`AlarmScheduler`, `AlarmReceiver`, `BootReceiver`), виджет (`JamalWidget`), отпечаток (BiometricPrompt),
  своё оформление уведомления (`NotificationUtil`, `res/layout/notif_reminder.xml`), значок уведомления — белый лист `res/drawable/ic_notification.xml` (с 74.1, раньше корона),
  каналы звука со звуком `res/raw/jamal_dawn.wav` (у канала Android звук не меняется — новый звук = новый канал, старый удаляется в `OLD_CHANNELS`). С 74.1: `jamal_life_dawn2` — громкие напоминания (`USAGE_ALARM`, громкость будильника, по умолчанию) и `jamal_life_dawn2_soft` — обычная громкость (`USAGE_NOTIFICATION_EVENT`); выбор — `lc_ui` → `loud` (мост `setLoudReminders`, версия моста 6), старый `jamal_life_dawn` в `OLD_CHANNELS`. Вибрация включена на обоих.
  С 72: будильник `stend_<этап>` за 10 мин до конца этапа показывает кнопки «Да / Перенести» (`AlarmReceiver.taskOf` → `stage:<id>`, `ActionReceiver` отдаёт оба действия веб-приложению через `PendingActions`). minSdk 26.
- **Windows** (`desktop/`): .NET WPF + WebView2, трей, напоминания в фоне; папка `desktop/Web` — копия веб-файлов. С 74.1 звук напоминания играет сама программа (`PlayChime`, `SoundPlayer` → `Web/sounds/jamal-dawn.wav`), поэтому его слышно и при окне в трее; страница узнаёт об этом по `window.__jlHostSound` и сама звук не играет (`hostPlaysSound`).
- **Копирование веб-файлов**: `node tools/sync-platforms.mjs` копирует 15 файлов в `android/app/src/main/assets` и `desktop/Web`.
  Эти копии в git не хранятся; источник правды — корневые файлы. **После любой правки веб-файлов запускать sync.**
- **Supabase**:
  - Auth по e-mail/паролю.
  - Таблица `public.life_state` (одна строка на пользователя: `user_id`, `state` jsonb, `schema_version` = 58, `updated_at`, `device_id`), RLS: только `user_id = auth.uid()` на select/insert/update/delete.
  - Таблица `public.ai_usage` (счётчик AI-запросов, лимит 10 в час), RLS на свои строки.
  - Таблица `public.life_state_history` (с 72, P7): `id`, `user_id`, `day`, `state` jsonb, `created_at`; уникально `user_id + day`; RLS select/insert/delete только свои строки. Приложение после синхронизации раз в сутки пишет снимок (`cloudDailySnapshot`) и удаляет свои копии старше 30 дней; восстановление — «Резервные копии» → «Облачные копии» (предпросмотр → подтверждение, `renderCloudCopies`).
  - Edge Function `life-control-ai` (`supabase/functions/life-control-ai/index.ts`, `verify_jwt: true`, import map `deno.jsonc`), текущая развёрнутая версия **v18** (72: ответ не дольше ~19 с — тайм-аут на модель 12 с, модель с 503 на 3 минуты в конец очереди, ошибка «Google перегружен» по-русски; AI получает отчёт дня, привычки-отказы, победы и этап цели).
- **CI** (`.github/workflows/release.yml`): на push в `main` — тесты → Android APK + Windows EXE → релиз. Тег берётся из `package.json`.
  APK подписывается ключом из секретов `ANDROID_KEY_ALIAS`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEYSTORE_BASE64`;
  Секреты добавлены 16.10.2026 (v70.0.913): APK подписан постоянным ключом владельца, обновления ставятся поверх. Шаг подписи сам убирает переносы строк из секретов и при ошибке называет неверный секрет.

### 73: приложение для всех (важно не сломать)
- **Название и версия.** Видимое имя — одна константа `APP_NAME` в `index.html` (`applyAppName()` ставит его в заголовок, экран входа, верх, «О приложении»), `app_name` в `android/.../values/strings.xml`, `<Product>` в `desktop/JamalLife.Desktop.csproj` (Windows читает его через `AssemblyProductAttribute`), `APP_NAME` в Edge Function. Версия — `APP_VERSION`, видна только в «Настройки → О приложении». Логотип (с 74.1) — зелёный лист, жилка-график вверх, золотая монета: исходник `icon.svg`; `node tools/make-icons.mjs` делает `icon-192.png`, `icon-512.png`, `icon-maskable.png` (maskable, рисунок в 80 %) и `desktop/app.ico` (16/32/48/256); Android — векторный `ic_launcher_foreground.xml` (масштаб 0,15, всё внутри круга 66dp), фон `#0F3A2F`, виджет `ic_widget_leaf.xml`; в шапке — тот же лист (`.jl-logo`).
- **Внутренние имена не менять:** пакет `com.doxajooon.lifecontrol`, ключ подписи, ключи localStorage (`LIFE_CONTROL_V52`, `JL_*`), IndexedDB `LifeControlDB`, таблицы, канал уведомлений `jamal_life_dawn2` / `jamal_life_dawn2_soft` (с 74.1 с согласия владельца; дальше меняется только описание), хост WebView2 `appassets.jamal-life` и папка данных `JamalLife` на Windows. Файлы релиза — `Life.apk`, `Life.exe`, релиз «Life vXX».
- **Значения по умолчанию нейтральные** (`DEFAULT`: доход 0, долги 0, пустая цель без этапов, шаблон дня `DAY_TEMPLATES.work`). Они влияют только на новое/пустое состояние. В облачной записи владельца все поля сохранены явно, поэтому его данные не меняются.
- **Новые настройки 73 и миграция (`applyV73` в конце `normalize`)**: «старый» пользователь = есть записи доходов, расходов, задач, заметок, привычек, побед или написанный/закрытый отчёт (`hasUserData`; отметки этапов, поставленные часами, не считаются). Без значения: `settings.quoteSet` → `'hadith'` у старого, `'general'` у нового; `debts.labels` → «Банк / Фирмы» у старого, «Долг 1 / Долг 2» у нового (переименовываются в окне «Долги»); `settings.onboarded` → `true` у старого. Ничего не привязано к почте.
- **Старые демо-значения ≤72** у аккаунта без единой записи (точное совпадение по хэшу, `clearLegacyDemo`) заменяются чистым листом; аккаунт с записями не трогается.
- **Первая настройка** (`openOnboarding`, 3 шага, каждый можно пропустить: имя и валюта → цель, сумма, срок, 1–4 этапа → шаблон дня или свои времена + долги). Открывается только после успешной синхронизации, когда в аккаунте нет данных и цели (`needsOnboarding`), и только один раз (`settings.onboarded`, уходит в облако). Закрыть окно = пропустить.
- **Цитаты дня** — «Настройки → Внешний вид → Цитаты дня»: Хадисы (375, `MOTIVATIONS`) / Мотивация (60 нейтральных мыслей, `GENERAL_QUOTES`) / Выключить. Идеи привычек и «советы для успеха» с намазом показываются только при «Хадисах».
- **Источники дохода**: Зарплата, Фриланс, Бизнес, Другое; «Спортивная аналитика» видна только тем, у кого уже есть такие записи (`profitSources`).
- **Первая выгрузка** (`cloudPushNow` без базы) ставит `JL_FIRST_PUSH_V73`; если приложение закрыли до ответа, при следующем старте облачная строка с `device_id` этого устройства считается своей старой копией и локальное состояние главнее (раньше правка, сделанная во время первой выгрузки на медленном телефоне, терялась после перезапуска). Чужая строка — как прежде, облако главнее (`mergeFirstContact`).
- **74.1 `settings.loudReminders`** («Настройки → Уведомления → Громкие напоминания (как будильник)», виден только в Android-приложении): без значения → `true` у всех (так решил владелец: напоминания бывало не слышно); сохранённый выбор не трогается (`applyV73`). Передаётся в Android при каждом `scheduleNative` (`syncLoudReminders`).
- `merge()` копирует значения по умолчанию (раньше вложенные объекты `DEFAULT` попадали в состояние по ссылке: у состояния без `habitLog` правка меняла сам `DEFAULT`, и снятая отметка «воскресала» при следующем `normalize`).

### Синхронизация (важно не сломать)
- Состояние сохраняется сразу локально (localStorage `LIFE_CONTROL_V52` + IndexedDB `LifeControlDB`) и уходит в облако через 2,5 с (`queueCloudSync` → `cloudAutoSync` → `cloudSync`).
- Запись в облако — только поверх известной версии (`PATCH ... &updated_at=eq.<base>`); при расхождении — трёхстороннее слияние `mergeStates(base, local, remote)` по `id` записей; база хранится в IndexedDB (`storeCloudBase`/`loadCloudBase`).
- Отметка базы `state._cloudBaseUpdatedAt` дублируется в `localStorage` `JL_CLOUD_BASE_STAMP_V68` (`rememberBaseStamp`/`baseStamp`) — без этого правка во время первой выгрузки терялась после быстрого перезапуска.
- Первый вход на устройстве без базы: `mergeFirstContact` — облако главнее, локальные записи добавляются сверху.
- Владелец устройства: `JL_DEVICE_OWNER_V64`; вход другим аккаунтом → `resetForNewOwner()` (чужие записи не смешиваются).
- Выход: если всё синхронизировано — `wipeLocalData()` стирает личные данные с устройства; без сети — предупреждение, ничего не стирается.

### AI (сервер, `supabase/functions/life-control-ai/index.ts`)
- Режимы: `life` (плюсы, минусы, «куда я иду», риск, план, шаг, советы по приложению; `lifeContext` + `facts` от клиента), `goal`, `week`, `deep`, `ping`; `GET` — бесплатная проверка.

## 5. Правила работы (обязательно)

1. **Ничего не ломать.** Перед коммитом: sync → `static_qa` → `edge` (16/16) → `e2e` (86/86) → `CPU_SLOW=4 e2e` (86/86). Новая функция — новый тест в `tests/e2e.mjs` и проверка в `static_qa`.
2. **Версия.** Каждый выпуск поднимает версию везде одинаково: `index.html` (`APP_VERSION='73.0'` и `id="appVersion">73.0</span>` в «О приложении» — на главном экране и экране входа версии нет), `sw.js` (`life-v73-0`), `package.json` и `package-lock.json` (`73.0.0`), `android/app/build.gradle` (`versionCode 730`, `versionName '73.0'`), `desktop/JamalLife.Desktop.csproj` (`73.0.0`), `tests/static_qa.mjs` (все эти ожидания). `schema_version` состояния остаётся **58**, пока не меняется формат данных.
3. **Данные пользователя.** Никаких изменений формата состояния без миграции в `normalize()`. Новая настройка без значения у существующего пользователя получает значение, сохраняющее его текущее поведение; правила, перезаписывающие сохранённые значения пустыми, запрещены. «Старый/новый» — только по данным, не по почте. Никаких деструктивных SQL и миграций в Supabase **без явного согласия владельца**. Реальную строку `life_state` не редактировать.
4. **Секреты.** Не коммитить ключи, пароли, keystore. Ключ Gemini — только в Supabase Secrets. Пароль владельца не спрашивать и не вводить.
5. **Edge Function.** Правка `index.ts` → деплой той же функции (`life-control-ai`, `verify_jwt: true`, import map `deno.jsonc`) → проверить логи Supabase (`function_logs`, строки `gemini ok` / `gemini error`).
6. **Дизайн.** Тёмная тема по умолчанию, светлая должна оставаться читаемой. Отступы между строками ≥ 4 px, текст ≥ 11 px, все анимации отключаются при `prefers-reduced-motion` и двигают только `transform`/`opacity` (static_qa проверяет). Без мерцания: не перерисовывать то, что не изменилось (`painter`, `textOf`, `dataset.sig`). Тосты — сверху, не над «+» и нижней панелью. Текст не обрезать «…».
7. **Деплой.** Push в `main` = релиз (веб обновляется через GitHub Pages, APK/EXE — в Releases). Коммиты с понятным описанием. Ветку `main` не переписывать (`--force` запрещён).
