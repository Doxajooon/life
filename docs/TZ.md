## 1. Что это за приложение

Jamal Life — личное приложение одного человека для управления днём, главной целью, деньгами и долгом.
Работает на Android (APK), в браузере (GitHub Pages) и на Windows (EXE); данные общие через Supabase.
Язык интерфейса — русский, валюта — сомони, часовой пояс — Asia/Dushanbe (UTC+5).

## 2. Архитектура

- **Одно веб-ядро** — `index.html` (~4 900 строк: вся разметка, CSS и JavaScript внутри, без фреймворков и сборщиков).
  Рядом: `sw.js` (офлайн), `manifest.webmanifest`, иконки, `fonts/` (Manrope, Nunito, Inter — woff2), `sounds/jamal-glass.wav`.
- **Android** (`android/`): Java, WebView + WebViewAssetLoader (`https://appassets.androidplatform.net/assets/`),
  мост `AndroidBridge` (версия 5): уведомления с кнопками «Готово / Через 15 мин» (`ActionReceiver`, `PendingActions`),
  будильники (`AlarmScheduler`, `AlarmReceiver`, `BootReceiver`), виджет (`JamalWidget`), отпечаток (BiometricPrompt),
  своё оформление уведомления (`NotificationUtil`, `res/layout/notif_reminder.xml`), канал звука `jamal_life_glass`
  со звуком `res/raw/jamal_glow.wav`. minSdk 26.
- **Windows** (`desktop/`): .NET WPF + WebView2, трей, напоминания в фоне; папка `desktop/Web` — копия веб-файлов.
- **Копирование веб-файлов**: `node tools/sync-platforms.mjs` копирует 13 файлов в `android/app/src/main/assets` и `desktop/Web`.
  Эти копии в git не хранятся; источник правды — корневые файлы. **После любой правки веб-файлов запускать sync.**
- **Supabase**:
  - Auth по e-mail/паролю.
  - Таблица `public.life_state` (одна строка на пользователя: `user_id`, `state` jsonb, `schema_version` = 58, `updated_at`, `device_id`), RLS: только `user_id = auth.uid()` на select/insert/update/delete.
  - Таблица `public.ai_usage` (счётчик AI-запросов, лимит 10 в час), RLS на свои строки.
  - Edge Function `life-control-ai` (`supabase/functions/life-control-ai/index.ts`, `verify_jwt: true`, import map `deno.jsonc`), текущая развёрнутая версия **v15**.
- **CI** (`.github/workflows/release.yml`): на push в `main` — тесты → Android APK + Windows EXE → релиз. Тег берётся из `package.json`.
  APK подписывается ключом из секретов `ANDROID_KEY_ALIAS`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEYSTORE_BASE64`;
  **пока секретов нет — подписывается временным ключом** (обновление поверх старой версии не ставится).

### Синхронизация (важно не сломать)
- Состояние сохраняется сразу локально (localStorage `LIFE_CONTROL_V52` + IndexedDB `LifeControlDB`) и уходит в облако через 2,5 с (`queueCloudSync` → `cloudAutoSync` → `cloudSync`).
- Запись в облако — только поверх известной версии (`PATCH ... &updated_at=eq.<base>`); при расхождении — трёхстороннее слияние `mergeStates(base, local, remote)` по `id` записей; база хранится в IndexedDB (`storeCloudBase`/`loadCloudBase`).
- Отметка базы `state._cloudBaseUpdatedAt` дублируется в `localStorage` `JL_CLOUD_BASE_STAMP_V68` (`rememberBaseStamp`/`baseStamp`) — без этого правка во время первой выгрузки терялась после быстрого перезапуска.
- Первый вход на устройстве без базы: `mergeFirstContact` — облако главнее, локальные записи добавляются сверху.
- Владелец устройства: `JL_DEVICE_OWNER_V64`; вход другим аккаунтом → `resetForNewOwner()` (чужие записи не смешиваются).
- Выход: если всё синхронизировано — `wipeLocalData()` стирает личные данные с устройства; без сети — предупреждение, ничего не стирается.

## 4. Тесты и проверки

```bash
npm install                    # один раз (Playwright 1.55)
node tools/sync-platforms.mjs  # после любой правки веб-файлов
node tests/static_qa.mjs       # должен закончиться строкой JAMAL_LIFE_V68_STATIC_QA_OK
node tests/e2e.mjs             # 42/42 passed; CHROME_PATH=... если Chromium установлен отдельно
CPU_SLOW=4 node tests/e2e.mjs  # то же на «медленном телефоне» — тоже 42/42
ONLY="часть названия" node tests/e2e.mjs   # один тест
```
- `tests/e2e.mjs` поднимает фальшивый Supabase (вход, `life_state` с версиями, AI-ответы) — реальная база не трогается.
- `tests/static_qa.mjs` проверяет версии во всех файлах, наличие шрифтов/звука, канал уведомлений, правила AI, отсутствие текста мельче 11 px, ключевые функции.

## 5. Правила работы (обязательно)

1. **Ничего не ломать.** Перед коммитом: sync → `static_qa` → `e2e` (42/42) → `CPU_SLOW=4 e2e` (42/42). Новая функция — новый тест в `tests/e2e.mjs` и проверка в `static_qa`.
2. **Версия.** Каждый выпуск поднимает версию везде одинаково: `index.html` (`brand-ver">V68`, `>V68<` на экране входа, `68.0</span>` в «О приложении»), `sw.js` (`jamal-life-v68-0`), `package.json` (`68.0.0`), `android/app/build.gradle` (`versionCode 680`, `versionName '68.0'`), `desktop/JamalLife.Desktop.csproj` (`68.0.0`), `tests/static_qa.mjs` (все эти ожидания). `schema_version` состояния остаётся **58**, пока не меняется формат данных.
3. **Данные пользователя.** Никаких изменений формата состояния без миграции в `normalize()`. Никаких деструктивных SQL и миграций в Supabase **без явного согласия владельца**. Реальную строку `life_state` не редактировать.
4. **Секреты.** Не коммитить ключи, пароли, keystore. Ключ Gemini — только в Supabase Secrets. Пароль владельца не спрашивать и не вводить.
5. **Edge Function.** Правка `index.ts` → деплой той же функции (`life-control-ai`, `verify_jwt: true`, import map `deno.jsonc`) → проверить логи Supabase (`function_logs`, строки `gemini ok` / `gemini error`).
6. **Дизайн.** Тёмная тема по умолчанию, светлая должна оставаться читаемой. Отступы между строками ≥ 4 px, текст ≥ 11 px, все анимации отключаются при `prefers-reduced-motion`. Без мерцания: не перерисовывать то, что не изменилось.
7. **Деплой.** Push в `main` = релиз (веб обновляется через GitHub Pages, APK/EXE — в Releases). Коммиты с понятным описанием. Ветку `main` не переписывать (`--force` запрещён).

## 6. Что нужно сделать

### 6.1. Делает владелец (не разработчик)
- [ ] Добавить в GitHub три секрета подписи (значения — в личном файле `jamal-life-podpis.txt`): Settings → Secrets and variables → Actions → New repository secret: `ANDROID_KEY_ALIAS`, `ANDROID_KEYSTORE_PASSWORD`, `ANDROID_KEYSTORE_BASE64`. Затем Actions → последний запуск → Re-run. Один раз поставить новый APK с удалением старого; дальше обновления ставятся поверх.
- [ ] Supabase → Authentication → Passwords → включить защиту от утёкших паролей (единственное замечание советника безопасности).
- [ ] Нажать «Запустить AI-анализ» и сообщить ответ. Если Google отвечает «лимит исчерпан» у всех моделей каждый день — включить оплату ключа в Google AI Studio.
- [ ] (по желанию) Supabase → Authentication → отключить самостоятельную регистрацию.

### 6.2. Делает разработчик — по порядку приоритета

**P1. Проверить AI на настоящем ключе и довести до рабочего состояния**
- После того как владелец нажмёт «Запустить AI-анализ» — посмотреть логи функции (`gemini ok <модель>` или `gemini error <модель> <код>`).
- Если все модели отвечают 429 — убедиться, что текст ошибки по-русски и что карточка «Разбор недели» и окно AI показывают разбор без AI (`localWeekText`, кнопка «Показать полный разбор без AI»).
- Если ответ есть — убедиться, что `aiTextHtml` разбивает его на карточки (заголовки ЗАГЛАВНЫМИ + тире). Если модель пишет иначе (markdown, нумерация) — поправить разбор, не промпт.
- Критерий: на реальном аккаунте разбор приходит или показывается понятная причина + разбор без AI; в консоли нет ошибок.

**P2. Доступность и клавиатура для новых элементов версии 68**
- Столбики графика долга (`.debt-bar-wrap[data-debt-open]`) открываются только кликом — добавить Enter/Space.
- Цитата `.jl-quote` раскрывается кликом — добавить `role="button"`, `tabindex="0"`, `aria-expanded`, Enter/Space.
- Критерий: axe 0 нарушений; всё открывается с клавиатуры; тест в e2e.

**P3. Светлая тема для новых компонентов**
- Проверить и при необходимости поправить контраст в светлой теме: карточка-чек формы денег (`.jl-receipt`), окно истории долга (`.jl-dh-*`), стикеры банка (`.jl-stickers`), плитки источников (`.jl-src-tiles`), полоски этапов (`.jl-ms-bar`), карточки AI (`.jl-ai-sec`).
- Критерий: снимки экранов 390×844 в светлой теме, текст читается (контраст ≥ 4.5:1 для обычного текста).

**P4. Платёж по долгу в итогах месяца**
- Сейчас расход с отметкой «платёж по долгу» (`expense.debtPayment`) входит в «Расход» месяца на «Деньгах», а в анализе (`analyzeLife`) — исключается. Сделать одинаково: в «Расход» не включать, а показывать отдельной строкой «Платежи по долгу: N» под итогами месяца.
- Критерий: тест — расход 300 + платёж по долгу 4000 → «Расход 300», «Платежи по долгу 4 000».

**P5. Автоэтапы цели — управление**
- Добавить в «Изменить цель» для каждого этапа переключатель «закрывать автоматически» (по умолчанию включён); выключенный этап `milestoneAuto` не трогает. Автоматически закрытый этап можно снять вручную, и он больше не закрывается сам (`m.autoOff = true`).
- Критерий: тест на оба случая; данные старых версий без новых полей работают.

**P6. Проверка на реальных устройствах (с владельцем)**
- Android: звук «Jamal Glass» звучит у новых напоминаний; кнопки «Готово / Через 15 мин» в уведомлении работают; виджет обновляется; отпечаток.

- Критерий: короткий отчёт владельца «работает / не работает» по каждому пункту; найденное — исправить.

**P7. Облачные резервные копии (только с согласия владельца)**
